## Текущая архитектура

- React 18 + TypeScript;
- Vite 5 + статический пререндер (SSG) через Puppeteer;
- Tailwind CSS + `src/index.css`;
- Framer Motion;
- React Router;
- React Hook Form + Zod;
- PHP-обработчик формы в `public/api/lead.php`;
- Яндекс.Метрика: `108988775`;

Команды:

```powershell
npm install
npm run dev
npm run build
npm run test
```

После сборки результат находится в `dist/`.

`npm run build` запускает `vite build`, затем `prerender.mjs`. Скрипт открывает собранную версию в headless Chromium и создаёт готовые HTML-файлы для `/`, `/privacy`, `/terms`, `/personal-data`, `/articles/vip-family` и `/articles/governess-salary`.

Не заменять эту команду на `vite build` без пререндера при публикации: тогда сайт снова будет SPA с пустым `#root` в исходном HTML.

### Важное состояние Git

На момент передачи рабочее дерево содержит незакоммиченные изменения, которые уже попадали в production-сборку. Последний отправленный коммит `f583625` содержит только возврат тёплой палитры, но **не является полным снимком текущего продакшена**.

Перед крупными правками:

1. изучить `git status` и `git diff`;
2. не выполнять `git reset --hard`, `git checkout -- .` и другие операции, которые могут удалить незакоммиченные изменения;
3. сделать проверяемый baseline-коммит только после просмотра всех отличий и согласования с владельцем;
4. не смешивать новые изменения с неизвестными существующими файлами без ревью.

### Публикация

1. Выполнить `npm run build`.
2. Загрузить содержимое `dist/` в document root домена.
3. Сохранить серверные файлы:
   - `api/lead-config.php` - содержит конфигурацию Telegram;
   - `.htaccess` - маршрутизация SPA, редиректы и защитные заголовки.
4. Не удалять файлы на сервере массово без резервной копии.
5. После публикации проверить:
   - `https://staff-academia.ru/`;
   - работу статических ассетов;
   - отправку тестовой заявки только по согласованному сценарию;
   - отсутствие ошибок в браузерной консоли.

Для развёртывания нельзя полагаться на `git pull`: на shared-хостинге нет рабочего Git-клона. Публикация происходит загрузкой собранного `dist/`.

## Формы и серверная часть

Фронтенд:

- `src/components/ApplicationForm.tsx` - поля, валидация, интерфейс формы;
- `src/lib/lead.ts` - формирование payload и запрос к API;
- `public/api/lead.php` - серверная валидация, антиспам, rate limit и доставка в Telegram;
- `public/api/lead-config.example.php` - безопасный пример конфигурации;
- `public/api/lead-config.php` - секретный серверный файл, игнорируется Git.

Endpoint:

```http
POST /api/lead.php
Content-Type: application/json
```

Payload: `name`, `contact`, `email`, `intent`, `page`, `submittedAt`, `utm`, `website` (honeypot).

Обработчик принимает только разрешённые Origin/Host, ограничивает размер payload и частоту до 5 заявок с IP в час. Заявки отправляются в Telegram. GetCourse пока не подключён.

## SEO и маршрутизация

- `index.html` - title, description, canonical, Open Graph;
- `public/robots.txt`;
- `public/sitemap.xml`;
- `public/.htaccess` - SPA fallback, редирект `www`, security headers.

Сайт работает как React-приложение в браузере, но production-сборка пререндерит шесть основных маршрутов в готовый HTML. Пререндер удаляет только начальные стили reveal-анимаций (`opacity: 0`), поэтому текст остаётся видимым и доступным для индексации без JavaScript. Для каждого маршрута `react-helmet-async` выставляет один уникальный `title`, `description` и canonical.

При изменении маршрутов обязательно обновить массив `routes` в `prerender.mjs`, добавить `Seo` в новую страницу и проверить результат `npm run build`.

## Правила работы

1. Сначала читать существующий компонент и последние согласованные материалы.
2. Не выдумывать биографии экспертов, отзывы, юридические условия, цифры агентства и обещания трудоустройства.
3. После правок выполнять минимум `npm run build`.
4. Проверять desktop, планшет и мобильную версию; карточки экспертов и формы - вручную.
5. Не коммитить и не публиковать `lead-config.php`, токены, пароли, архивы, временные файлы и диагностику SSH.
6. Перед публикацией на прод проверять `git diff`, чтобы в сборку не попали не относящиеся к задаче изменения.
